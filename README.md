# CS 300: Data Structures and Algorithms

## What was the problem you were solving in the projects for this course?

Throughout this course, I worked on two projects that focused on developing a course advising program for computer science students. 
The program needed to store course information, display courses in alphanumeric order, and allow users to search for individual courses and their prerequisites. 
For Project One, I compared three different data structures: vectors, hash tables, and binary search trees, to determine which would be the most appropriate for the program. 
In Project Two, I applied what I learned by developing a working C++ program that used a hash table to organize and retrieve course information.

## How did you approach the problem? Consider why data structures are important to understand.

I started by looking at how each data structure worked and comparing their runtime efficiency, memory usage, and overall advantages and disadvantages. 
One thing I found interesting was that even though all three structures could accomplish the same task, they each handled storing and retrieving information differently. 
For example, a binary search tree could display courses in order without needing an additional sorting step, while a hash table generally allowed for faster searches. 
I ultimately decided that a hash table would be the best choice because I felt that quickly finding individual courses and their prerequisites was more important for this particular program.
This helped me understand why choosing the right data structure is such an important part of designing software.

## How did you overcome any roadblocks you encountered while going through the activities or project?

One of the more challenging parts of this course was working with the different data structures, especially when implementing the binary search tree. 
Understanding how nodes and pointers worked together took some time, and I had to work through several issues before everything functioned correctly. 
I also encountered challenges with reading course information from files and making sure the program handled incorrect or missing information appropriately. 
I found that breaking the code into smaller sections and testing things individually made it much easier to figure out where problems were occurring. 
Although troubleshooting could be frustrating at times, it helped me become more comfortable working with C++ and understanding what my code was actually doing.

## How has your work on this project expanded your approach to designing software and developing programs?

Before taking this course, I think I was more focused on getting a program to work rather than considering whether there might be a better or more efficient way to accomplish the same thing. 
These projects helped change that perspective because I had to compare multiple approaches before deciding which one made the most sense. 
I also learned that just because one data structure works well in a certain situation doesn't necessarily mean it will be the best option for every program. 
Going forward, I think I'll spend more time considering how information needs to be stored, accessed, and organized before jumping straight into writing code.

## How has your work on this project evolved the way you write programs that are maintainable, readable, and adaptable?

I think one of the biggest things I've taken away from this course is the importance of writing code that is organized and easy to understand, rather than just making sure it produces the correct output.
Throughout these projects, I got more practice separating different tasks into functions, using descriptive variable names, and including comments to explain what certain sections of the code were doing. 
I also became more aware of the importance of input validation and error handling, especially when working with information being loaded from external files. 
These are things I want to continue improving because I know that being able to understand and modify existing code is just as important as being able to write it in the first place.
